# 共同群组、设置搜索与拖动预览复查

2026-10-22，基于 b34627 发布后的源码，处理共同群组列表未显示完整、设置页搜索缺少 Pro 设置、Pro 搜索状态切换异常，以及消息菜单拖动预览中的开关形状问题。本轮 **13.0 / b34628** 已[正式发布](https://github.com/RegramDev/Regram-ios/releases/tag/v13.0-b34628)；旧 b34627 IPA 不包含这些修改。上一轮顶部标记横条的窗口与遮罩修正一并纳入，见[横条复查](navigation-community-badge-fixes.md#横条后续复查b34628)。

## 共同群组

用户反馈标题显示 20 个共同群组，列表只显示 17 个且无法继续滚动。此次检查发现两个独立的分页风险：

- 请求游标此前取自已显示列表的最后一项，缓存预览或提示群组也会参与，可能跳过服务端页。现独立保存 API 返回的最后一个原始 chat ID；首个成功页替换旧缓存预览，迟到的缓存与提示不能覆盖新页。
- 列表底部偏移可能在加载期间发出，加载完成后若条目／偏移没有变化，不一定再次触发分页。现于行事务和布局完成后再次检查；没有可显示条目时也允许继续读取下一页。

失败保留已显示群组和游标，增加明确的重试行；不自动循环重试网络错误。空页或重复游标结束分页，完成后的标题计数按实际加载条目收敛。正常的「首批 17 个、下一批 3 个」应累积为 20 个，并去除页边界的重复项。无法访问或服务端不再返回的群组不会通过构造本地条目补足。

[Telegram API 文档](https://core.telegram.org/method/messages.getCommonChats)将 `max_id` 定义为返回 chat ID 的分页边界；使用最后一个原始响应条目与缓存显示数据分离，是本次实现的选择。

## 设置搜索的完整路径

- 设置页右下角搜索接入 `RGSettingsCatalog`。Pro 入口及具体设置使用独立、可保存到最近搜索的标识；具体结果通过共享设置解析器直接打开对应页面和控件，避免再跳到另一个搜索页。SettingsUI 和 RGProUI 通过 AccountContext 的工厂接口连接，不引入依赖环。
- Pro 首页的无结果提示和正常分类此前复用 ID `1`，原生文本行与 disclosure 行无法相互更新，可能导致事务无法完成，清空后也无法恢复。无结果提示改用独立 ID。分类页标题也改用独立 ID，避免与隐私页第一个控件重复。
- 延后的输入回调只提交最新一笔修改。搜索框关闭自动纠正和自动大写，正在编辑时由原生文本框保有文字；旧列表事务不再改写较新的输入、清空状态或中文输入法的组合文字。其他设置输入框保留原有模型更新行为。
- 原生设置搜索始终提交无结果的空列表，清空或只输入空白时恢复最近搜索；近期条目在首次布局前已返回时也会正常应用。FAQ 初次网络响应不再阻塞本地设置查询，搜索状态信号不再强持有自己的页面。
- 原生设置搜索和 Pro 搜索共用标题、页面、别名及 Unicode 匹配逻辑；搜索与设置深链继续共用页面解析和已有定位逻辑。

## 消息菜单拖动预览

原来逐层复制 CALayer 的预览路径不能完整保留原生 UISwitch 的形状／合成信息。本次只为允许拖动的开关行改用 UIKit 快照；原始开关、点击、排序存储和拖动完成后的原节点恢复路径保持既有处理。普通开关行不启用这一覆盖。

## 验证与交付边界

本轮检查不使用真实账号。分页回归执行生产回调和预加载判断，覆盖缓存替换、17+3、边界重复、失败重试、空页／重复游标，以及加载状态转换后补查底部偏移，均通过。搜索回归执行生产条目生成、列表合并、目录匹配、原生适配器和输入回调：三种语言下 507 次列表合并、27 个分类布局的唯一标识检查、732 次规范化目的地工厂请求通过，覆盖搜索／无结果／清空及原生空结果状态切换。工厂接口使用测试替身，不等于在应用内打开了 732 个页面。现有回归检查 51/51 通过；适配器语言读取修正后搜索专项再次通过。

独立 UIKit 应用已在 iPhone 17 Pro／iOS 26.5 模拟器验证输入法组合文字、清空、正常输入框更新和 UIKit 开关快照。该环境的旧开关快照未出现截图中的方块，因此没有把它记为问题复现；新快照显示正常。本机没有 iOS 27 模拟器，也没有执行真实账号共同群组、完整应用内搜索或真机拖动验收。
