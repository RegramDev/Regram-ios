# 二维码令牌超时与证书文件导入


## 二维码登录


- 二维码页显式使用应用前台状态激活当前待登录账户，迁移或重建连接后重新绑定该状态及登录令牌事件。
- 暂时性的 RPC 错误恢复三秒重试；无效 API 配置停止重试并显示错误。图像继续使用主题色。
- 在尚未显示首个令牌时，第一次请求超时会重建当前待登录账户的连接。操作只允许 `.empty`／`.phoneEntry` 状态，重置该记录的认证密钥映射，并在同一 DC 创建新网络；已登录账户、验证码和密码输入状态不执行这个重建。
- 连接重建完成后必须交回登录序列，即使用户已关闭二维码页。手机号页也同步使用更新后的账户和网络，避免退回后继续调用旧连接。

匿名主机检查使用当前构建的 API 配置，独立的内存会话客户端在 3.95 秒收到令牌；仓库自己的 MTProto 代码、协议层 230 也收到 `auth.loginToken` 结果。未登录任何真实账户，未打印或保存令牌及认证密钥。这验证了当前配置和主机传输可以导出令牌，不能证明手机的原始超时原因或真机扫码过程已经成功。

## 证书导入

- 采用原生 `UIDocumentPickerViewController`，由更新页保留选择器代理，使用复制导入模式。文件提供器即使没有正确识别证书类型也可以选中。
- 在原生选择器退场完成后处理结果及显示提示，避免导入错误提示与选择器的关闭动画冲突。
- 用最多 256 KB 加一个字节的文件读取检查大小，避免文件提供器尚未提供大小元数据时直接判错。支持 P12、PFX 和 `.mobileprovision`。
- 选中后显示导入进度；错误类型、空文件、过大文件、读取失败、密码或证书不匹配均提供反馈。取消选择不触发错误。

主机检查覆盖扩展名大小写、中文文件名、边界读取及失败分类，同时检查二维码的重试策略和六组彩色渲染／解码。原生文件提供器点选、手机上实际显示令牌、扫码接受、跨 DC 和二步验证需要真机复测。

本轮修复版本为 b34593，已通过 `//Telegram:Regram` arm64 Release 完整构建。构建未使用真实账户登录，也未在真机执行文件点选或扫码接受。

b34593 参考 IPA 保留六个扩展，安装标识和权限与 b34592 一致；十二个 arm64 可执行文件的 ad-hoc 签名及配套 dSYM 校验通过。该包仍需使用自己的 LCSign 证书签名后安装。

## b34594：添加账号的直连与证书保存

后续真机反馈明确了场景：已有账号后添加新账号，未使用应用内代理时令牌请求超时，开启代理后能显示二维码。这证明该场景可以完成令牌获取和绘制；代理同时改变传输路径和重建连接，尚不能据此确定设备上的具体失败地址。

- 扫码前优先使用同一环境中现有账号的数据中心及服务端发现的地址，创建待登录账号自己的连接，减少对初始 DC2 种子地址的依赖。只复制路由信息，不复制已登录账号的认证密钥、授权或令牌。
- 连接切换后继续交回登录序列，关闭旧连接；即使二维码页在初始化期间关闭，也完成账户对象的交接。没有现有账号时仍使用正常初始化流程。
- 更新登录界面上下文时，保留同一个待登录账号的前台连接绑定，避免把新的绑定覆盖为暂停。
- 超时提示根据当前连接状态区分无网络、连接超时、连接初始化超时和令牌请求超时，便于真机反馈定位，不显示令牌或认证密钥。
- 导入反馈改为应用自己的窗口弹窗，由原生弹窗组件处理按钮触摸及关闭。
- 证书数据、密码和显示名称写入同一条本机钥匙串记录；旧版记录继续兼容读取。使用 `AfterFirstUnlockThisDeviceOnly`，不上传、不经 iCloud 同步、不存入更新缓存。回到前台或受保护数据恢复可用后重新读取，避免锁屏启动时一次读取失败被误认为未导入。
- 主动移除证书会删除证书记录、旧名称记录和导入的描述文件。保持安装身份及钥匙串访问权限的覆盖更新可继续读取，证书本身的有效期仍取决于签发者。

存储回归检查见 `Regram/RGAppUpdate/Tests/run-credential-persistence-checks.py`：在独立模拟器应用中使用合成数据检查进程重启、覆盖安装、旧记录读取及主动移除，不接触真实证书或账号。真机不开代理的添加账号流程，以及完整文件选择后点击提示按钮，仍需设备复测。

b34594 已通过 `//Telegram:Regram` arm64 Release 完整构建和最终增量核对。独立 iOS 26.5 模拟器中的存储、进程重启、覆盖安装、旧记录读取及移除检查全部通过；原生匿名 MTProto 主机检查在 DC2 和 DC4 都获得令牌，未登录真实账号。最终参考 IPA 保留六个扩展，安装身份及权限与 b34593 相同；全部 arm64 Mach-O ad-hoc 签名及主 App／扩展 dSYM UUID 校验通过，三个新增超时提示与证书保存说明已从最终包中逐项核对。

后续用户确认切换网络节点后二维码可以正常显示，并要求停止排查。本轮未记录失败节点的路由或远端连接地址，因此不能把某项源码差异认定为根因。b34595 沿用 b34594 的应用行为，提高构建号，用于验证从 GitHub Release 发现更新、本机签名及 LCSign 覆盖安装的完整过程；完整更新仍由实际设备验证。

证书导入流程已改为一次多选 P12／PFX 和描述文件，选择完成后弹出密码输入框，验证全部材料后保存；页面不再要求预先填写密码。TrollStore 安装用户可在更新页选择对应方式，无需导入证书。详见 [更新与安装](app-updates.md)。
