# Regram 功能与性能复核

复核日期：2026-09-27。代码基线为 `2fbea86e25` 加当前工作区修改。按照本轮要求，没有运行 Xcode、Bazel、Swift 编译、IPA 打包或发布，也没有使用真实账号做破坏性操作。

## 复核结论

此前审计中能通过代码定位的问题已经逐项处理。消息过滤器现在由统一的规则快照、后台过滤和未读投影驱动，过滤消息仍然进入系统通知流程；聊天列表、话题列表、聊天页未读数和应用内总未读数使用同一份投影。空通知只保留角标更新并按当前 request 标识延时清理，通知扩展的角标统计恢复为轻量原生 Postbox 查询，避免扩展超时。

代码层面暂未发现新的 tree-sitter Swift 语法错误。类型、目标依赖、旧系统 API 和真机行为仍需要在用户指定的 Xcode 26.6 环境中完成编译和隔离设备验证后才能宣称发布可用。

## 消息过滤器的实现约束

规则默认为正则，内容匹配开关和从选中文本添加的规则使用普通内容匹配。缓存采用有界环形淘汰；规则变化会增加 generation，旧 generation 的异步结果不会写入当前结果缓存。导入文件限制为 2 MiB、4096 条规则、单条 pattern 最多 4096 个 UTF-16 单元，并且去重键包含 pattern、匹配模式和会话范围。

未读投影不写服务器已读状态。Postbox 的受影响会话通知覆盖消息变化、阅读状态、聊天列表变化、通知设置、话题状态和外部事务刷新。没有启用过滤器时，“下一个未读频道”保留原先的首个匹配快速路径，不会因为投影代码遍历全部会话。
