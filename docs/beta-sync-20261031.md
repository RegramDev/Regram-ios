## TestFlight 使用

进入 **Actions → TestFlight → Run workflow → regram-beta**。

- `publish`：构建、上传、关联 External Testers 并提交 Beta App Review，`build_number` 留空。
- `build`：只验证签名和构建，不上传。
- `distribute`：填写已上传的构建号，重试外部分组和送审，不重新构建或上传。

默认分支须有手动工作流入口，GitHub 才提供 Run workflow。`master` 的同名入口只提示选择 Beta，不读取签名 Secret 或执行构建／上传。完整说明见 [TestFlight](../build-system/ci/TESTFLIGHT.md)。推送代码仍按原有 Build Regram 工作流生成参考 IPA，不会自动发布到 TestFlight 或 GitHub Releases。

## 首次 TestFlight 构建与依赖修正

原因是首次合并保留了 Beta 的旧子模块指针，却合入了较新的 Swift 包装层。旧 Rust FFI 没有包装层需要的 `MTAuthKeyCreatedTemporary`、`MTAuthKeyCreatedPermanent`、`mt_session_drain` 和 `MTEventKindReleased`。只做目标分析不会发现 Swift 引用缺失。
