# Regram 自动更新与安装

入口：**设置 → Regram Pro → 管理与工具 → Regram 更新**。本文描述 b34619 的流程；发行一份 Regram IPA，包含主应用及六个扩展。

## 更新来源与网络

更新器使用系统 `URLSession` 读取本项目 [GitHub Releases](https://github.com/RegramDev/Regram-ios/releases) 的最新正式版：

```text
https://api.github.com/repos/RegramDev/Regram-ios/releases/latest
```

发布标签使用 `v13.0-b34619` 形式，IPA 使用 `Regram-13.0-b34619.ipa` 形式。版本比较、标签、唯一候选文件名、下载路径、文件大小及 GitHub 资产 `digest: sha256:…` 均需通过检查；缺少 SHA-256、草稿、预发布、降级或重复候选不会用于更新。文件下载后继续检查包内版本、主应用及扩展结构与安装身份。

**检查更新不要求导入证书。**「打开 GitHub Release」是独立按钮，点击才打开发布页；检查到新版本身不会跳浏览器。

检查、下载及清单请求使用系统 HTTP 网络，没有接入 Telegram 的 SOCKS5／MTProto 代理或原生 DNS／IP 策略。开启应用内 Telegram 代理不代表 GitHub 请求也走该代理；系统 VPN、网络分流、DNS、GitHub 连通性或服务限流均可能影响检查。页面报告失败时，应区分发布信息请求、IPA 下载、签名及清单／安装阶段；Telegram 聊天可用不能证明 GitHub 可达。

## 检查与提示

| 设置／状态 | 行为 |
| --- | --- |
| 自动检查 | 默认关闭；开启后启动及回前台最多每六小时检查一次 |
| 自动检查关闭 | 不显示全局更新提醒，包括缓存恢复后的提醒；仍可在更新页手动操作 |
| 自动下载及签名 | 默认关闭；开启会同时开启自动检查，关闭自动检查也关闭自动下载 |
| 发现新版 | 先提示；开启自动下载后点击更新可留在当前界面静默下载及准备 |
| 准备完成 | 提示安装，安装由用户发起；签名需要在前台继续 |
| 缓存已就绪 | 恢复准备／安装阶段，不再次当作发现新版或重新下载 |
| 重复事件 | 同一进程按更新资产及阶段去重，跨账号和前台切换共用 |
| 手动更新 | 手动检查／下载不额外触发发现新版弹窗；结果在更新页展示 |

临时检查失败不会使已校验、仍适用的安装缓存失效。失败提示提供进入更新页恢复的入口；后台完成后等待回前台再提示安装。

## 下载、缓存与安装后清理

IPA 交给系统后台 `URLSession` 下载，保存任务与目标资产信息，进程重新运行时接回任务。进度来自实际传输字节；百分比、已下载／总大小在信息可用时显示，校验／签名等阶段使用状态提示。HTTP 重定向和最终来源必须符合允许的 HTTPS 发布域名，下载后校验大小、SHA-256 和包结构，不能仅凭文件名安装。

校验后的原始 IPA、签名 IPA 和元数据保存在不参与系统备份的专用 Application Support 目录：

- 原始文件跨重启复用，签名失败或更换证书／描述文件后可重新签名，不要求再次下载。
- 发布说明修改不改变资产指纹；资产改变、文件损坏或签名身份不符时相应缓存失效。
- 签名缓存绑定证书、描述文件、安装身份及当前构建号；安装前重新校验证书有效性。
- 取消终止下载任务并清理未完成传输；临时签名材料在操作结束后删除。
- **新版启动时**将本机版本／构建号与缓存目标比较，确认已安装目标或更高版本后删除原始 IPA、签名 IPA、缓存记录及旧任务，不要求开启自动检查。
- 安装请求发出或完整文件交付后先保留缓存，便于安装失败重试；已导入证书、密码及描述文件继续保存在钥匙串。

这不是无限后台执行承诺。系统调度、权限和用户强制退出会影响下载；后台下载完成不等于已经完成前台签名或安装。

## 证书签名安装

1. 点击「导入 P12 与描述文件」，同一次选择一份 P12／PFX 和所需 `.mobileprovision`，然后输入密码，再统一验证和保存。失败不更改现有配置，不要求提前填写密码。
2. 当前安装包内能提取的匹配描述文件会保存，因此有可用文件时也可只导入 P12。后续导入的描述文件合并去重；单次最多选择 16 个文件，最多保存 64 份描述文件。
3. 准备更新前检查当前主应用和每个扩展的证书、有效期、应用标识及权限。允许同一通配符描述文件用于它实际匹配的多个目标；不要求机械地准备七份不同文件。
4. 缺失、过期、证书不符、应用标识或权限不匹配时，显示对应主应用／扩展与原因，停止准备流程。证书应与当前安装版匹配，以满足覆盖升级要求。
5. 使用内置 zsign 在设备上签名，保留安装版实际 Bundle ID、`application-identifier`、URL Scheme、App Group、钥匙串组及完整扩展集合。两种标识分别核对，不用后缀猜测签名身份。
6. 签名完成后点击安装，通过下述 LCSign 清单和本机下载通道交给 iOS。

证书、私钥、密码和描述文件保存在本机非同步 Keychain，不进入设置备份；IPA、证书及密码不上传给 LCSign。签名器的 OpenSSL 使用 `RGUpdateSSL_` 独立符号，避免与 Telegram 网络的 BoringSSL 混用；构建和回归检查保持这两套加密实现隔离。

签名器来源及许可证见 [zsign 适配说明](../Regram/RGUpdateSigner/Vendor/zsign/UPSTREAM.md)。这些匹配检查不代替 Apple 签名信任、证书准入及设备安装资格。

## LCSign 清单与 iOS 安装

使用 [LCSign 节点列表](https://support.lcsignx.com/install/services) 和公开清单接口，不需要自建服务或 LCSign 存取码：

1. 临时服务只绑定 `127.0.0.1`，向本机安装器提供已签名 IPA，支持 HEAD、完整 GET 及 Range。
2. 向所选节点 `POST /ota/manifest` 提交应用标识、版本／构建、标题及临时本机下载 URL，取得令牌。
3. 在创建令牌的同一节点使用 `/ota/m/{token}`，核对清单内容；节点失败可尝试其他节点。
4. 使用 `itms-services://?action=download-manifest&url=…` 请求系统安装。

打开 URL 只代表系统接收请求。只有实际 IPA GET 才算安装器开始读取，HEAD 不计；三十秒没有读取会提示重试并保留签名包。Range 区间合并后完整覆盖文件才算完成交付，不能据此断言系统安装成功。

安装通道使用系统允许的有限后台时间，最长保留五分钟；取消、到期或进程退出时关闭。证书方式可开启「安装时自动退出 Regram」，默认关闭，仅在完整交付后退出；请求被拒绝、没有读取或只读取部分文件时不退出。最终结果以新版启动的版本号为准。

## TrollStore 安装

更新页选择 **TrollStore（巨魔）**。能够读取当前容器的 `_TrollStore` 标记时默认选择，否则可手动选择；不将 URL Scheme 可打开当作已正确安装的证明。切换方式保留原始下载及证书。

1. 使用同一 GitHub Release、大小和 SHA-256 校验。
2. 核对包版本、主应用及全部扩展的 Bundle ID、执行文件、App Group 和钥匙串组；不匹配则停止，无需 P12／描述文件，也不重签。
3. 点击安装后通过回环通道提供现有本机 IPA，使用 `apple-magnifier://install?url=…` 交给 TrollStore，不重新下载，也不调用 LCSign 清单。
4. 需要在 TrollStore 中开启 URL Scheme；未配置时系统可能打开其他应用，三十秒没有 IPA 请求会给出提示。是否出现安装确认由安装器设置决定。

完整交付只显示更新包已交给安装器。安装失败可复用缓存重试，新版启动后再清理；覆盖升级应保留原应用身份及数据容器。

## 灵动岛与锁屏实时活动

iOS 16.1 及以上支持「在灵动岛与锁屏显示更新进度」，默认开启。具有灵动岛的设备提供紧凑、最小及展开视图，其他支持实时活动的设备使用锁屏视图。

- 使用 Regram 图片，显示目标版本、实际下载进度、校验、签名或准备完成状态；非下载阶段不制造百分比。
- 后台下载完成但还需签名时提示打开 Regram 完成准备。
- 点击通过已配置并注册的应用 URL Scheme 进入更新页，避免误选网页协议而打开空白浏览器。
- 展开布局避开摄像头区域，版本按原字符串展示；取消、失败、关闭显示或新版启动后结束旧活动。
- 由本机 ActivityKit 更新，不依赖 APNs 或额外推送服务器，不授予额外后台执行时间。系统暂停期间可能显示上次状态。

Actions 构建和人工确认发布是两条流程，详见 [GitHub Actions](github-actions-build.md)。正常发行只提供一份 `Regram-版本-b构建号.ipa`，更新器不选择多身份资产；身份、权限及文件校验仍保留。

b34619 的完整构建、IPA 身份／签名／调试符号校验和 SHA-256 校验通过；通知实验、预览行数及图标持久化尚待真机验收。

b34618 已完成 Xcode 27 arm64 Release、主应用及六扩展包校验、IPA 大小与 SHA-256 校验，安装身份和权限与 b34617 一致。用户于 2026-10-15 确认的真机验收对应 b34616；b34618 的共同群组发言和返回动画尚未记录真机验收结果。主机适配／合成检查与用户设备反馈分别记录。
