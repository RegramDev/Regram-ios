# 频道广告片段过滤与本机纠错

本轮基于已发布的 13.2 / b34652，当前语义过滤开发版构建号为 b34655。入口为「Regram Pro → 隐私与过滤 → 消息过滤器 → 广告过滤与样本」；消息长按菜单提供「标记广告 / 纠正过滤」，已清理的消息提供「查看原文 / 纠正过滤」。设置入口整行均可点击。

## 自动处理

b34655 在原有片段规则之外接入随 IPA 分发的 MiniRBT 语义分类模型，以 Core ML 在本机运行。模型读取消息文字、说明和按钮标题，不上传消息，不访问链接目标。每个用户安装同一版本即可使用同一模型，无需先手动标注。训练来源、评估方法和限制见[本机语义模型](ad-semantic-model.md)。

按完整句子和段落判断推广意图，结合开头正文及空行分块检查上下文。混合消息只去掉有把握的广告片段，保留正常文字、资源入口和媒体；确认整条为推广卡片时隐藏该条消息及其媒体、按钮。引用格式的广告价目表只有整条推广判定才能隐藏，代码仍受保护。自定义表情、链接和 UTF-16 实体边界不会被从中间截断。按钮按标题及被删除广告的完整目标处理，保留正常下载、播放、搜索等入口。

过滤只生成显示副本，不修改 Postbox 或服务端消息。聊天历史和置顶栏使用相同判断；不添加“已过滤广告”等替换文字。长按保留消息可查看原文，临时显示被隐藏内容可恢复整条广告。后台处理有输入、缓存和时间限制，超限或模型不可用时保留内容。首屏可能先显示原文，判断完成后刷新，滚动中的过期任务会合并。

频道资料页将「关键词过滤」和「智能广告过滤」放在一个原生分组卡片中，共用底部说明。关键词规则隐藏整条消息；语义过滤清理广告片段，两者开关独立。智能广告过滤按账号、频道保存，默认继承账号总开关，总开关关闭时单频道不能强行开启。自动广告过滤设置中可查看本机模型是否已就绪。

范围为普通频道消息的正文、说明、按钮和置顶摘要。聊天列表摘要、系统推送以及图片／视频像素中的广告尚不参与语义识别；富文本文档、秘密聊天、一次性或受保护内容不参与自动处理。短暗语、纯图片推广、与正文不可分割的软文仍可能漏判，也可能误判，不能保证完全识别。

## 自动记录与可选纠错

浏览频道时，已识别的广告会自动记录为待确认样本，包括原文、去掉的范围、按钮及整条隐藏状态；重复浏览不重复记录。自动记录不会直接参与本机纠错或模型训练。长按漏判消息可手动加入样本，打开编辑页只生成草稿。初始红色区域来自自动建议，只有「确认并保存」才形成已审阅样本；未标记的文字视为正常，按钮和媒体默认待定。原文不可编辑；用户可框选「正常／广告／待定」、一键全正常或全广告，并预览结果。选择自动对齐完整字符、链接及自定义表情边界。手动媒体标注只记录类型与标签，不保存媒体文件；自动整条推广判定可以隐藏整条媒体消息。

样本按账号保存在账号目录的 `regram-ad-samples-v1`，排除系统备份；原文快照不可变，消息编辑或媒体替换产生新的快照。相同快照重开可继续编辑。确认后的长广告片段仅在同一频道精确复用；按钮按标题及完整目标复用；正常或待定标注阻止冲突学习。删除记录后取消从它派生的偏好。最多保存 10,000 条，满后暂停收集并在设置页显示提示，不自动淘汰用户记录；读取损坏数据会报错，不覆盖原文件。

## 公共版本改进

设置提供两种导出：「全部记录」包含待确认样本供后续审核；「已确认训练集」只包含已确认且没有待定标签的记录。机器原始判断保存在独立的 `detection` 字段，人工纠正不会覆盖该字段。两者均导出为版本化 JSONL：`schemaVersion: 1`，`offsetUnit: utf16`；`input.text` 是原文，`spans` 采用左闭右开范围，`normal/ad/uncertain` 分别对应正常、广告、待定；按钮通过原始行列 ID 独立标注。`sourceGroup` 由本机随机盐与来源 ID 派生，用于分组评估，不导出原始账号／频道 ID。原文和链接本身仍可能含个人信息，所以导出前明确提示用户核对，只有主动分享后才离开设备。

公共规则或模型应在自愿提供并审核的样本上改进，通过按频道和广告模板分组的留出集检验，再随新版 IPA 分发给所有用户。自动预测不能直接充当训练真值；待定区域不作为负样本。重点评估正常内容误删、广告残留、按钮误删、混合消息正文保留和设备耗时，不能用整体准确率掩盖误删。私人纠错不会自动变成全局规则，应用没有自动上传、后台训练或远程模型订阅。

## 引用与剧透显示

“自动显示剧透内容”现在也作用于气泡中的回复／引用预览、回复输入栏及其照片／视频缩略图，包含剧透范围内的自定义表情。切换设置会更新文本排版缓存、遮罩和缩略图模糊状态；关闭后恢复遮罩。原始剧透实体保持不变，原有秘密媒体等限制保持有效。

## 验证

`swift test --package-path Regram/RGAdFilter` 检查正文保留、实体偏移、链接和引用边界、整条媒体判定、分词一致性、存储和账号隔离。`Tools/run-bridge-checks.py` 使用生产桥接逻辑验证独立开关、原文恢复、稳定刷新、滚动缓存和置顶缓存隔离。`Tools/run-semantic-checks.py` 使用实际 Core ML 模型验证分词、转换误差和整条消息投影；同一 Swift 检查器可编译到 iPhone，输入和报告留在忽略目录。

当前开发记录位于 `build-input/ad-filter-34655/`，其中包含真实消息的文件不提交。具体模型指标及实际验证范围见[本机语义模型](ad-semantic-model.md)。构建、设备运行、参考包静态校验分别记录，单元检查不能代替完整应用编译或覆盖升级。
