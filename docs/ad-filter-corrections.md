# 频道与群聊广告过滤及本机纠错

本轮在 13.2 / b34658 语义过滤开发版上继续修正，当前构建号为 b34659。入口为「Regram Pro → 隐私与过滤 → 消息过滤器 → 广告过滤与样本」；消息长按菜单提供「标记广告 / 纠正过滤」，已清理的消息提供「查看原文 / 纠正过滤」。设置入口整行均可点击。

## 自动处理

b34655 在原有片段规则之外接入随 IPA 分发的 MiniRBT 语义分类模型，以 Core ML 在本机运行。模型读取消息文字、说明和按钮标题，不上传消息，不访问链接目标。每个用户安装同一版本即可使用同一模型，无需先手动标注。训练来源、评估方法和限制见[本机语义模型](ad-semantic-model.md)。

按完整句子和段落判断推广意图，结合开头正文及空行分块检查上下文。混合消息只去掉有把握的广告片段，保留正常文字、资源入口和媒体；确认整条为推广卡片时隐藏该条消息及其媒体、按钮。引用格式的广告价目表可以随整条推广卡片隐藏；使用引用样式的招商页脚，只有完整段落、各行、相邻多个推广入口及专门训练的引用上下文判断都提供强证据时才清理。正常引言后的引用示例优先保留。一般引用和实际代码仍受保护；仅含短 ASCII 字母、数字、下划线或连字符的优惠码格式，可随完整推广卡片隐藏。明确的「标签：#广告」元数据按所在完整区域处理，混合其他主题的分类行及引用示例不作这一扩展。公开标记推广的消息若将自然语言简介排成等宽代码块，仍需整条语义判定才可一起隐藏；仅有标签不足以删掉这类块，含实际编程语法的块继续保护。自定义表情、链接和 UTF-16 实体边界不会被从中间截断。按钮按标题及被删除广告的完整目标处理，保留正常下载、播放、搜索等入口。

完整说明均判定为广告且没有保留按钮时，隐藏该条附图；同一 Telegram 相册中没有独立说明的媒体继承整条广告判定。保留的正常说明、按钮、人工标记正常或待定的媒体阻止相册连带隐藏；不依据相邻消息推断独立图片。相册附图也独立记录为待确认样本。

主页列表先清理完整消息，再生成文字、自定义表情和缩略图；纯广告回退到该会话本地最近 50 条中的正常消息，无可用消息时只留空预览，会话行仍保留。保留排序、草稿和未读状态，不因 AI 判定发送已读回执。每批查询最多 16 个会话，最多缓存 128 个会话；b34661 起逐条判断回退候选，找到正常消息即停止，同一相册保持完整，未准备好的旧消息不会先被当作正常回退。已完成的摘要先显示，其余会话继续处理；多个列表独立管理任务，共享相同消息的有效判断，原有关键词过滤的行为保持不变。修正原因与对照见[主页等待修正](ad-preview-latency-34661.md)。

过滤只生成显示副本，不修改 Postbox 或服务端消息。频道与群聊的聊天历史、置顶栏和主页聊天列表使用相同判断；不添加“已过滤广告”等替换文字。长按保留消息可查看原文，临时显示被隐藏内容可恢复整条广告。后台处理有输入、缓存和时间限制，超限或模型不可用时保留内容。首屏可能先显示原文，判断完成后刷新，滚动中的过期任务会合并并取消，关闭聊天或置顶订阅会释放对应任务；不同窗口互不取消。模型暂时不可用或超时不会被缓存为正常消息，已有确定片段继续展示清理结果，其余内容保留并按约一分钟间隔请求重试。

同一文件夹在分页或重连时短暂返回空的加载状态，会保留最近的已加载会话行；真正空结果或切换文件夹会清空旧行。广告结果只产生普通内容更新，不重复首次加载或滚动指令，推理进行中也持续接收过滤设置变化。

任务在后台队列按消息分批、公平调度，跨历史、置顶、主页复用结果，输入张量复用以减少分配。b34662 把缓存／确定规则与模型调度分开，推理不会阻塞已有结果和刷新；每条模型调用仍不可中断，按实际耗时安排后续推理间隔。后台与 critical 热状态暂停后续推理，省电模式和 serious 热状态增加间隔，不改变模型阈值或跳过待处理消息。首次识别可能更慢，实际温度和续航需要设备测量。本地验证包的改动与对照见[响应优化记录](ad-filter-latency.md)。

频道与群聊资料页将「关键词过滤」和「智能广告过滤」放在一个原生分组卡片中，共用底部说明。关键词规则隐藏整条消息；语义过滤清理广告片段，两者开关独立。智能广告过滤按账号、会话保存，默认继承账号总开关，总开关关闭时单会话不能强行开启。自动广告过滤设置中可查看本机模型是否已就绪。

范围为普通频道、普通群和超级群收到的正文、说明、按钮、置顶摘要和聊天列表预览；话题列表同样清理预览。私聊与自己发送的消息保持原样。系统推送以及图片／视频像素中的广告尚不参与语义识别；富文本文档、秘密聊天、一次性或受保护内容不参与自动处理。短暗语、纯图片推广、与正文不可分割的软文仍可能漏判，也可能误判，不能保证完全识别。

## 自动记录与可选纠错

浏览频道或群聊时，已识别的广告会自动记录为待确认样本，包括原文、去掉的范围、按钮及整条隐藏状态；重复浏览不重复记录。自动记录不会直接参与本机纠错或模型训练。长按漏判消息可手动加入样本，打开编辑页只生成草稿。初始红色区域来自自动建议，只有「确认并保存」才形成已审阅样本；未标记的文字视为正常，按钮和媒体默认待定。原文不可编辑；用户可框选「正常／广告／待定」、一键全正常或全广告，并预览结果。选择自动对齐完整字符、链接及自定义表情边界。手动媒体标注只记录类型与标签，不保存媒体文件；自动整条推广判定可以隐藏整条媒体消息。

b34662 另加可重建的已确认记录索引，减少启动时对待确认文件的读取，原样本文件及导出格式不变。完整模型判断的跨重启缓存与训练记录分开保存，复用时仍以人工纠正为先。详见[重启与样本读取优化](ad-filter-restart-cache.md)。

样本按账号保存在账号目录的 `regram-ad-samples-v1`，排除系统备份；原文快照不可变，消息编辑或媒体替换产生新的快照。相同快照重开可继续编辑。媒体标注按消息和附件快照匹配，不会把一张无文字图片的标注套到其他无文字图片上。确认后的长广告片段仅在同一会话精确复用；按钮按标题及完整目标复用；正常或待定标注阻止冲突学习。删除记录后取消从它派生的偏好。最多保存 10,000 条，满后暂停收集并在设置页显示提示，不自动淘汰用户记录；读取损坏数据会报错，不覆盖原文件。

## 公共版本改进

设置提供两种导出：「全部记录」包含待确认样本供后续审核；「已确认训练集」只包含已确认且没有待定标签的记录。机器原始判断保存在独立的 `detection` 字段，人工纠正不会覆盖该字段。两者均导出为版本化 JSONL：`schemaVersion: 1`，`offsetUnit: utf16`；`input.text` 是原文，`spans` 采用左闭右开范围，`normal/ad/uncertain` 分别对应正常、广告、待定；按钮通过原始行列 ID 独立标注。`sourceGroup` 由本机随机盐与来源 ID 派生，用于分组评估，不导出原始账号／频道 ID。原文和链接本身仍可能含个人信息，所以导出前明确提示用户核对，只有主动分享后才离开设备。

公共规则或模型应在自愿提供并审核的样本上改进，通过按频道和广告模板分组的留出集检验，再随新版 IPA 分发给所有用户。自动预测不能直接充当训练真值；待定区域不作为负样本。重点评估正常内容误删、广告残留、按钮误删、混合消息正文保留和设备耗时，不能用整体准确率掩盖误删。私人纠错不会自动变成全局规则，应用没有自动上传、后台训练或远程模型订阅。

## 引用与剧透显示

“自动显示剧透内容”现在也作用于气泡中的回复／引用预览、回复输入栏及其照片／视频缩略图，包含剧透范围内的自定义表情。切换设置会更新文本排版缓存、遮罩和缩略图模糊状态；关闭后恢复遮罩。原始剧透实体保持不变，原有秘密媒体等限制保持有效。

## 验证

`swift test --package-path Regram/RGAdFilter` 检查正文保留、实体偏移、链接和引用边界、整条媒体判定、分词一致性、存储和账号隔离。`Tools/run-bridge-checks.py` 使用生产桥接逻辑验证独立开关、原文恢复、稳定刷新、滚动缓存和置顶缓存隔离。`Tools/run-chat-list-checks.py` 使用生产桥接、预览逻辑和 SwiftSignalKit 检查回退、取消、编辑、相册、群聊和元数据保留。`Tools/run-semantic-checks.py` 使用实际 Core ML 模型验证分词、转换误差和整条消息投影；同一 Swift 检查器可编译到 iPhone，输入和报告留在忽略目录。

本轮另复核手机新增 33 条快照（22 个不同输入、14 个来源组）；用户明确要求保留 Long Emby 欢迎／使用说明及相关官方入口。已确认的表情广告沿用同一来源的既有人工纠错，单独记录为个性化规则验证，不能算作文字模型识别图片的能力。

当前开发记录位于 `build-input/ad-filter-34659/`，其中包含真实消息的文件不提交。具体模型指标及实际验证范围见[本机语义模型](ad-semantic-model.md)。构建、设备运行、参考包静态校验分别记录，单元检查不能代替完整应用编译或覆盖升级。
