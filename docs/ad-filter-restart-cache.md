# ReSieve 重启与样本读取优化（b34662）

2026-11-16，接着[响应优化](ad-filter-latency.md)减少重复工作。模型、阈值与计算后端没有变化。源码与专项验证完成后，按要求构建了 b34662 本地验证包，完整应用和包校验结果见文末。

## 已经判断过的消息不必重跑模型

之前的语义缓存只存在内存里，退出应用后就丢失。现在按账号保存完成的模型判断，重新打开后用消息的精确输入查找。正文、链接、实体、按钮或来源发生变化就不能命中；显示时仍先应用当前规则与人工纠正。媒体人工纠正仍绑定原消息快照，不能套用到另一条恰好文字相同的消息。

缓存文件不保存正文、链接目标或原始来源 ID，只存账号盐派生的指纹、判断范围、概率、按钮位置和时间。它不是训练集，不会自动转为人工标注。已有广告记录继续保存在原样本库中，二者用途不同。

- 最多保留 1,024 条、512 KiB 估算内存，替代上一阶段 1 MiB 的语义缓存；显示结果预算仍为 7 MiB，模型分数缓存仍为 2 MiB。这不是整个进程的内存上限。
- 有效期为七天。应用构建号、系统版本、模型清单或预测算法版本变化后失效。修改预测语义时需要更新缓存算法版本。
- 文件校验失败、超限或读取失败时退回重新判断。未完成的推理不写入缓存，也不能因为缓存损坏而认定消息正常。
- 文件写入合并后交给独立 I/O 队列，采用原子替换，后台切换和内存告警时尝试保存。异步写入失败只影响下次复用；尚未写入就退出时，下次会重新计算。账号已删除时，排队的写入不会重建账号目录。

## 启动时只读取人工纠正

以前为了找到人工纠正，每次启动都要解码并检查全部待确认记录。现在增加一个可重建的已确认记录索引。索引有效时，只读取相应原文件；样本原文、文件位置及导出格式都不变。

索引有校验和，并记录样本目录的修改时间。应用以原子替换方式写入样本，新增、纠正、删除后都会更新索引；旧版本写入也会使索引失效。缺少或损坏索引时完整扫描一次。完整记录页和导出仍检查全部原文件；可选索引不会阻止关闭开关或删除记录。

## 本地验证

2020 条合成记录中包含 20 条人工纠正，分别用修改前、修改后的存储实现读取，返回的纠正集合完全相同：

| 操作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 第一次扫描 | 214 ms | 386 ms，包含建立索引 |
| 新建存储实例后再次读取，三次 | 215 / 355 / 550 ms | 6.9 / 6.1 / 6.0 ms |

首次建立索引仍要读取全部记录，这次测量没有首次扫描提速。以上是 Mac 上文件缓存和机器负载共同影响下的样本，不是 iPhone 启动速度。

另以实际 Core ML 模型、82 条本地输入和生产桥接代码执行独立进程重启对照。最终验证从过滤会话初始化开始计时，约 **284 ms** 后 82 条全部就绪，模型调用及模型窗口数均为 **0**；正文、按钮、隐藏状态的最终摘要与重新推理相同。只计算初始化之后的批次处理，曾测得约 89 ms；补计初始化的两次测量约为 178 和 284 ms，不能把 89 ms 当作完整启动耗时。这里也没有包含 Telegram 数据库、网络和界面绘制。

首次处理未缓存输入仍需要模型。测试期间主机负载有明显波动，因此不使用这轮首次批量耗时来宣称模型本身提速。

```sh
swift test --package-path Reza/RGAdFilter
python3 Reza/RGAdFilter/Tools/run-restart-checks.py
python3 Reza/RGAdFilter/Tools/run-store-latency-checks.py
python3 Reza/RGAdFilter/Tools/run-bridge-checks.py
python3 Reza/RGAdFilter/Tools/run-latency-checks.py
```

78 项 Swift 测试通过。独立进程回归使用生产桥接、存储和缓存，模型替换为可计数的确定性适配器，验证重启不重复调用、人工纠正优先、消息编辑重判、版本变化失效，以及缓存损坏且模型不可用时保留未完成状态。桥接和排队回归另行检查原有显示行为；适配器耗时不作为 Core ML 性能结论。

报告和真实样本留在忽略目录 `build-input/ad-filter-cold-cache-20261116/`。本轮未在手机执行新代码，不能据此给出手机发热、续航或总内存峰值的改善比例。
