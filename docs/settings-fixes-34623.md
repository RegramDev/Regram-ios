# b34623 分组、手势、设置定位与导入修正

基线为已发布 b34622 的 `40c5d9dece8235c41f845c9ca9c45db7f61bf97a`，复用现有 `Telegram-iOS-pin-fix` 工作树并建立 `codex/startup-folder-audit` 分支。原工作树的 rules_apple 兼容补丁及 Bazel 链接保留；原主目录中的 macOS 窗口和构建脚本改动不在本轮范围。

## 修正

- 分组设置中的「启动时打开分组」改为行内显示当前值、点击直接弹出选择。无需进入独立页面。选择具体分组仍按账号保存，切换模式保留原分组映射。旧 `startupFolder` 页面深链与 `rememberLastFolder` 深链统一定位到这行，搜索只保留一个入口。三种语言说明同步。
- 根设置页的列表行使用按钮，旧右滑代理排除了所有按钮，使滑动在行内松开时仍触发菜单。现在只允许列表行按钮参与返回手势，真实开关、输入框及横向控件继续保留自身手势；行按钮移动超过阈值便取消点击和高亮，即使底栏显示时也不会把横滑当点击。
- 原生设置页深链／全局搜索跳转后，目标行显示短暂的主题色填充和边框；提示不接收触摸。等待列表事务后寻找实际目标节点，离开页面取消旧回调。
- 「隐藏私聊活动状态」作用于本机收到的对方输入、录音等活动提示；幽灵模式在 TelegramCore 的网络路径抑制本机向外发送的状态，功能并不重复。前者重命名为「隐藏对方输入与录音提示」，新增三种语言说明，保留偏好及旧链接。
- 聊天文件名匹配 `regram-settings*.json` 时才生成「导入设置」动作；多选、一次性媒体与声明超限文件不生成该项。下载超时或解码失败显示错误，不更改设置。有效文件进入已有分类预览与恢复确认，复用原生底栏偏好恢复逻辑；文件选择器和消息导入共用容量及格式校验。

## 额外审查

1. 新增功能的备份只测试了字典导出，实际 JSON 解码会将分组映射及多个枚举值当作 Bool 拒绝。本轮先通过实际编码→解码复现 `features.startupFolders` 错误，再补齐对应类型和枚举校验；补充真实文件读取、容量与错误格式回归。
2. `features.chatListStartupFolderMode` 不在备份白名单，恢复具体分组映射后仍可能采用其他模式。现已纳入外观分类；旧备份只带 `rememberLastFolder` 时也会替换当前显式模式。
3. 删除当前分组时 `(0 ..< index - 1)` 在索引为零时会形成非法范围，且跳过紧邻前项。改为反向遍历 `prefix(index)`，覆盖首项、前项存活、缺失与当前项仍有效的情况。
4. 同时检查设置搜索／深链、跨账号映射、过滤器导入、自动机器人查询的草稿边界及邀请批量撤销的主链接／管理员保护。未执行真实账号或网络业务操作；这不是全仓库安全审计结论。
