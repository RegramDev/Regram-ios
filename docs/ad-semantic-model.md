# 本机广告语义模型（b34657）

本版将训练后的 MiniRBT H256 模型随 IPA 分发，使用 Core ML 在本机判断中文消息的推广意图。保留正常软件分享、开源推荐、官方福利，以及本轮明确确认保留的频道相关 ITIN 代办、eSIM 套餐／预售和教程入口。其他商业推广仍按片段或整条清理，不加入“已过滤广告”占位文字。无需用户先标注，没有消息上传、后台联网训练或自动模型下载。同版本用户使用同一模型，本机纠错仍可选且按账号隔离。

## 训练与来源

基础模型为 HIT／iFLYTEK 的 `hfl/minirbt-h256`，约 1,035 万参数、六层 Transformer、FP16 权重。来源版本、许可和摘要见 [RGAdModelSources.json](../Regram/RGAdFilter/Resources/RGAdModelSources.json)，复现步骤见 [Training/README.md](../Regram/RGAdFilter/Training/README.md)。公开来源包括 Chinese-Spam-Dataset、bayes_spam_sniper 已审核记录，以及 tg-ad-guard-bot 的开发对照。基础模型采用 Apache-2.0；公开语料未找到明确的数据集许可证，原始语料不随仓库或安装包分发。

在原有 b34656 检查点基础上，本轮从经授权的手机导出读取 325 条快照，共 24 个匿名来源组；其中新增 102 条、涉及 11 个来源组。按本轮最终保留标准审核后，新增记录为 22 条正常、11 条纯广告、66 条混合消息、3 条仅靠文字无法判断的媒体记录。自动检测范围没有直接变成训练标签；手机上的人工标注没有被改写。

72 条新增记录用于适配，25 条熟悉尾栏用作回归；3 条媒体记录及 2 条含歧义／旧模板的记录不计入新增文字训练。最初隔离的 26 条曾参与开发检查，随后纳入适配，**不再属于未见测试**。按来源分组后还检查了转发和近似文本，避免把同一内容从不同频道转发当成独立证据。

采用的增量阶段共 4 + 3 + 3 + 4 轮；另外 3 轮和 4 轮候选因正常内容退步或保留政策校正未采用。最终训练包含 9,301 条简繁、片段和窗口扩展行，另回放 7,899 条原公开训练数据；这些行数不是独立广告数量。难例只从已审核训练输入选取，增加五倍采样权重，并检查规范化后的相反标签。

本轮补充了与 Swift 完全一致的分词窗口：每窗 126 个正文 token，重叠 16 个，尾窗对齐全文末尾，最多八窗。直接保留 token ID，避免从词中间切开后重新编码改变输入。最终加入 72 条这类窗口训练行。验证／测试输入不加入训练。

阈值选择仍要求公开验证 precision ≥ 98.5%、正常类 FPR ≤ 0.5%，再比较作者编写的域内验证集中的正常保护和召回。最终片段阈值为 **0.99368**，它是决策边界，**不是准确率**。公开测试集在选定检查点后计算，本轮多次作为历史对照使用，不能当作全新的外部评估。

## 显示与保护

- 中文正文包含拉丁产品名时仍可评估；不支持的外文正文保持保守处理。
- 正常正文、广告尾栏、按钮和媒体分别判断。混合消息按原始 UTF-16 范围删除，重算文字实体，保留原始消息，避免改写或生成正文。
- 同一行的独立导航链接分别判断；Telegram 拆开的同目标连续链接先合并，避免删掉标题中几字。两三个字的菜单项需要自身高分、相邻推广项和组合文本共同支持，才能扩展删除。
- 价格、上线状态和带链接的参考标题需要正文上下文支持。已完整删除的推广链接之后，只有空白相隔且目标完全一致的裸联系方式可以随之清理；人工确认内容关闭该项推断。
- 纯广告附图和同相册无独立说明的附件可随整条隐藏；正常正文、按钮或人工保留媒体会阻止连带删除。代码、引用、独立资源链接继续保护，不按相邻关系删除独立图片。
- 频道、普通群、超级群、置顶和主页预览使用同一套结果。主页从本地最近 50 条逐步寻找正常预览，保持排序、草稿和未读数。
- 在后台执行 CPU 推理并复用缓存，有输入和时间上限；首屏可能先显示原文，完成后刷新。ANE 转换概率未满足原有对照容限，因此未启用 ANE。

## 本轮验证

| 项目 | 结果 | 范围 |
| --- | --- | --- |
| 公开文本基准 6,663 条 | Precision 97.73%；Recall 34.29%；正常类 FPR 0.83%（TP 1163、FP 27、FN 2229、TN 3244） | 噪声垃圾信息标签下的分类器指标，不是实际广告覆盖率 |
| 作者编写的域内验证 55 条 | 正常 30/30 保留，推广识别 24/25 | 用于检查点／阈值选择 |
| 外部机器人开发输入 87 条 | 正常 48/48 未判广告，推广识别 13/39 | 原始文字分数，未套用显示保护，仍有漏判 |
| 完整开发回归 426 条 | 363 条含正常正文均保留；252/252 条含广告文字完整清理；63/63 条纯广告隐藏；194/194 条混合消息完整清理 | 旧 322 条、新手机 97 条、编写压力用例 7 条；全部属于开发证据 |

广告范围内的非空白字符必须全部消失，只去掉联系方式仍算失败。按最终保留标准重算旧版 b34656 在同一批输入中的原始投影，曾有 13 条正常内容被损伤、31 条广告未清完；本版开发回归对应为 0 和 0。按钮同样逐项检查，没有用文字分数代替最终显示结果。

实际 iPhone 16 Pro（iOS 27.0.1）使用同一生产模型、分词器和投影器运行 426 条输入，结果与 macOS 对照一致，100 条模型转换输入及 12 条完整分词窗口边界对照通过。整条消息判断中位约 80 ms、P95 224 ms；模型冷加载约 25 ms。这是包含缓存复用的 Xcode 诊断程序数据，不是完整应用滚动帧率，也不代表新 IPA 已覆盖安装。

原始样本、候选检查点、失败记录、真机报告、Release 构建及 IPA 验收保存在忽略目录 `build-input/ad-filter-34657/`。安装包验收还核对实际模型资源及编译后权重与真机检查程序的一致性。

本模型尚不识别图片／视频像素或音频，也不保证识别暗语、软文或未知语言。当前输入是消息文字和结构，**并未实现对任意频道主题的可靠自动理解**；本轮保留的相关服务内容来自明确审核的样本政策。系统通知不参与此次显示投影。开发样本零误删、零残留不能推导出实际使用零误判。
