# 本机广告语义模型与显示路径（b34660）

本文保留 b34660 的模型与验证记录。后续 b34662 的运行时改动见[响应优化](ad-filter-latency.md)和[重启缓存](ad-filter-restart-cache.md)。

Reza 使用 ReSieve 判断中文消息中的推广意图。模型基于 MiniRBT-H256，约 10.35 百万参数，通过 Core ML 在本机运行。它不上传聊天内容，不在后台联网训练，也不显示「已过滤广告」占位文字。正文夹带广告时，只裁掉确认的推广部分；整条广告连同图片、链接预览和按钮一起隐藏，数据库中的原文保留。

本版补充了用户提供的 8 条典型广告，包括搜索群引流、机场优惠、充值促销、服务推荐和长篇产品软文。重复提供的链接只算一个样本。7 条来自公开消息嵌入页，另 1 条通过 Xcode 读取手机里的原文、引用、链接及媒体结构；后者的验收没有套用手机上刚保存的个人纠错。网页嵌入页不提供完整内联键盘，所以网页样本只验证实际取得的结构。

## 保留和清理的边界

正常分享、开源工具、去广告讨论、官方福利、入群验证，以及此前审阅的相关 ITIN／eSIM 服务样本继续保留。Long Emby 欢迎说明、使用指南和相关官方入口也保留。这些是明确的内容政策和已审阅样本，不代表已经可靠理解任意频道的主题。

- 文本按句段、空行上下文和独立菜单入口判断。短资源标题、正常引言、真正代码、报告中的引用和不确定内容有保留检查。
- 当确认删除的广告占正文至少 60%，且不少于 12 个有效正文字符时，单独留下的链接可以随广告一起移除。链接两侧最近的正文都必须属于广告；相邻正常说明、明确保留的入口和引用／代码会阻止扩展。URL 长度不参与比例计算，人工精确纠错不走这项自动推断。
- 没有直接挂链接的招商说明，需要整段、每个有效句子、至少两个相邻推广入口及合并上下文共同支持，才随推广菜单清理。引用样式的招商页脚另外要求经过训练的引用上下文判断，不能仅凭广告词删除引用。
- 短篇更新说明可能被拆成标题、版本和改动三个小段。整条删除之前，若至少三个开头段落分别及联合判断都属于正常内容，会保留这部分正文，避免长广告尾部吞掉短正文。
- Telegram 优惠码的等宽格式可能多包了空行；格式周围的空白不再导致整条广告被保护。内部空格、语法和真正的代码仍走原有保留逻辑。
- `#ad`、`#广告`、`#推广` 等 35 种完整推广声明按消息、章节和句段边界处理。URL 片段、代码、引用示例及多主题分类中的标签不会直接扩展为整条广告。
- 频道、普通群、超级群、置顶和主页预览共用处理结果。相册继承还受正常说明和人工媒体纠错约束，不能因为同组有一条广告就无条件隐藏所有图片。

## 未读、回复和设置界面

已读收尾现在同时检查关键词和 ReSieve 的隐藏结果。只有最新历史已完整加载、用户位于底部，且阅读位置之后连续都是已确认隐藏的消息，才推进已读位置；未读的正常消息、尚未判断的消息、加载空洞和其他会话／话题都会阻止推进。全部隐藏的窗口也可收尾。「@」导航会先在后台判断当前目标，再跳过隐藏的提及；主页预览不发送已读回执。36 项纯逻辑检查覆盖这些边界。

正常回复不会因为被回复的消息是广告而消失。整条广告目标的引用头和缩略图从显示副本移除；混合目标使用清理后的正文，单独保存的引用文本还要核对原始范围。正常引用继续保留，引用了已删除广告则回退到清理后的预览。输入框里的回复预览也使用同一检查，发送所用的原始回复关系不变。只准备已经加载的一层回复目标，每批最多 128 条；未加载的目标和没有原消息的独立引用不猜测为广告。

消息过滤器中的自动过滤入口、启用项及单个会话开关统一使用「ReSieve」，与关键词规则分组显示。记录入口改为「过滤记录与纠错」，导出操作放在长记录列表之前，避免滚动到底才找得到。启用状态与暂不可用状态分别显示，三种语言均已更新，沿用现有 Telegram 主题、原生开关和分组列表。

## 模型和数据记录

本版模型标识为 `2026-11-16.10`，ReSieve 仓库版本为 `1.1.0`。模型与词表、公开来源版本、训练阶段关系和文件摘要见 [RGAdModelSources.json](../Reza/RGAdFilter/Resources/RGAdModelSources.json)。训练脚本和输入规则见[训练说明](../Reza/RGAdFilter/Training/README.md)。

本轮沿用已独立审阅的手机样本，加入 8 条用户明确指定的广告，以及旧样本中尚未完整删除的推广片段和正常内容对照。最终阶段有 11,415 条简繁、片段和窗口扩展行，另回放 7,899 条原训练数据；这些数字不是独立广告数量。少量已审阅难例增加采样权重，但没有把模型自己的检测结果当成标注答案。

训练选择继续要求公开验证集 precision ≥98.5%、正常类 FPR ≤0.5%，再比较域内验证的误判和召回。候选经过回退与修正，最终接受第 37 阶段的第 2 个 epoch，阈值为 **0.99164**。阈值不是准确率。原始消息、账号资料、标注、训练划分和候选权重都留在忽略目录，没有放进模型仓库。

基础权重来自 HIT／iFLYTEK MiniRBT-H256，声明 Apache-2.0。公开文字来源包括 Chinese-Spam-Dataset、bayes_spam_sniper 审核记录和 tg-ad-guard-bot 开发用例；基础模型许可不等于这些语料也使用同一许可。模型库保存完整推理权重、词表、配置、依赖版本、本地来源说明和署名，无需再下载基础模型；不重新分发原始语料。

939 条回归中有 4 条使用此前明确的个人媒体纠错，单独记录，不能算作文字模型识别图片的成绩。只有广告范围内全部非空白字符都消失才算完整删除，只去掉联系方式算失败。

本版更偏向避免误删：相比 b34659，公开历史基准正常类 FPR 从 0.95% 降到 0.70%，召回从 33.34% 降到 27.36%；外部机器人开发用例识别的推广从 16/39 降为 9/39，正常误判从 1 条降为 0 条。因此不能描述成所有指标都提升，也不能用本轮开发回归零残留保证陌生广告都会被识别。

66 项单元检查、生产桥接和主页预览专项检查，以及 86 项通用功能检查通过。完整应用还必须构建 `//Telegram:Reza`，并校验最终 IPA 内的模型和三种语言资源。构建源码摘要、通用功能检查和包验收保存在本轮忽略目录 `build-input/ad-filter-34660/`。

## 响应速度与耗电

置顶候选现在与聊天历史同时加载，后台工作按置顶、当前聊天、主页预览的顺序优先处理；每四次插队会让最早的任务继续，避免其他列表一直等待。主页先处理当前会话的顶部预览，再处理用于回退的旧消息。

第一条及置顶判断完成后，可以提前触发原有合并刷新，最快约 20 ms，并限制为每秒最多 5 次；其余批次继续合并刷新。桥接测试中，已经由规则确定的置顶广告从提交到收到通知约 35 ms，这不是模型冷启动时间或手机界面实测。

单块、强推广、没有引用／代码／菜单／不透明按钮的完整卡片会复用已有整块分数，避免再逐句重复推理。跨页面结果缓存、固定输入张量复用、取消过期工作和失败重试都保留。低电量和热状态继续增加休息，后台或严重发热时暂停；调度不改变判定阈值。

在调度修改阶段、尚未加入本轮内存与回复改动时，使用同一旧模型和 82 个输入的 macOS 生产桥接对照中，两版首次都调用 56 次分类、运行 515 个模型窗口，后续置顶、主页及第二文件夹均未重复推理。首次处理 CPU 时间分别为 5.91 s 和 6.14 s，墙钟时间为 17.20 s 和 18.06 s；检查时还有其他进程运行，这组数据不能证明首次批量推理整体提速。改动主要减少前台重要消息的排队和刷新等待。重复显示读取 16,400 次分别用了 0.122 s 和 0.085 s CPU 时间。

完整消息开发回归的 macOS 观测中位耗时为 54.8 ms，P95 为 197.0 ms，包含缓存命中与并行检查的影响。以上都不是手机温度、电量或最终 IPA 的滚动实测，不能换算成降低多少度或节电百分比。

内存复用缓存现在同时限制条数和估算载荷：文本分数最多 2,048 条／2 MiB，每账号跨页面结果最多 2,048 条／8 MiB。当前窗口另行保留自己的判断，避免共享缓存淘汰后广告重现；窗口完成后移除旧窗口记录。账号注册表不再永久持有已离开的会话，取消的任务即使处于后台暂停状态也会释放捕获的消息。运行时只读取已确认样本来构建个人规则，不把整份待确认记录库保留在内存中。

这些数值是缓存的估算有效载荷限制，不是整个 App 的内存上限。真实内存警告会释放可重建的共享分数和模型，普通切换页面保持模型常驻，避免频繁重新加载引起额外耗电。当前窗口、模型运行库、媒体和界面仍有各自的占用，尚无新包的手机 RSS 对照测量。

## 仍需观察的场景

本轮通过 Xcode 读取已安装版本的消息；最终 IPA 的覆盖安装、偶发主页空白、温度和续航仍需在新包上观察。主页代码继续保留加载期间已有会话行，真实空结果和切换文件夹则正常更新，单元或适配器检查不能替代长时间真实使用。

图片／视频像素、音频、未知语言、暗语和模糊软文仍可能漏判；正常内容也不能保证永不误判。模型更新随应用分发，设置里的记录和人工纠错继续可用，个人纠错不会自动上传成所有人的规则。
