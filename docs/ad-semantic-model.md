# 本机广告语义模型（b34658）

本版继续将训练后的 MiniRBT H256 模型随 IPA 分发，使用 Core ML 在本机判断中文消息的推广意图。新增 `#ad`、`#广告`、`#推广` 等发布者广告声明的结构化识别，修复推广链接中问号造成的广告残留，并用手机新增样本继续训练。保留正常软件分享、开源推荐、官方福利，以及此前明确确认保留的七条频道相关 ITIN 代办、eSIM 套餐／预售和教程入口。无需先手动标注，不显示“已过滤广告”占位文字；同版本用户获得同一模型，没有原文上传、后台联网训练或自动模型下载。

## 标签和完整消息处理

- 完整匹配 35 种明确商业声明，包括 `#ad`、`#ads`、`#advertisement`、`#sponsored`、`#paid_promotion`、`#promotion` 及简繁中文变体，忽略大小写。`#admin`、`#advice`、`#adblock`、`#广告设计` 等不会因子串相同命中；`#福利`、`#推荐` 不作为广告声明。
- 独立声明标签在消息／分隔区域首尾时描述该区域，句中或独立段首声明按句段边界处理；代码、被引用的标签示例、URL 片段和文章中间的多分类标签行受到保护。独立标签夹在两段正文之间时，只向相邻段落扩展。没有可靠边界时仍可能存在歧义，不能据此承诺任意混排都完美分段。
- 明确标注的纯广告可以连同价格引用、复制用的短兑换说明、按钮和附图隐藏。真正的代码继续保护；混合消息保留正常正文及独立资源链接。语义模型也会独立判断未标标签的推广。
- 修复 `?`、`!`、`;` 等 URL 查询字符被切成句子的问题。分段时遵守 Telegram 的链接实体边界，避免链接保护反过来留下整段推广。没有删除或改写原始数据库消息。
- 短教程／资源引言带独立链接、后续推广指向其他目标时，增强整条消息保留判断。入群验证、审核、投票等不透明回调按钮，不再仅凭短标题单独判为广告。
- 频道、普通群、超级群、置顶与主页预览继续使用共用结果；同相册附件的继承、草稿、排序和未读数规则保持原有机制。未引入图片 OCR 或视频识别。

## 本轮样本与训练

通过 Xcode 实际查看了资源、影视、科技三个频道和 Stash 群；可见正常内容整理为 11 条保留检查。手机安装的是 b34657，这些显示文本不是原始消息完整性的证明。

经本机导出取得 617 条记录、34 个匿名来源组，比上一轮新增 292 条记录，去重后为 264 个新输入。独立复核其中 58 条、涉及 13 个来源组：11 条正常、37 条混合、10 条纯广告。其余 234 条新增记录没有被自动当作已标注训练真值；歧义和纯图片记录没有凭猜测加入文字标签。原文、账号数据、候选检查点和导出文件均保留在忽略目录。

另加入用户明确确认的 [7412](https://t.me/zhetengsha/7412) 和 [957](https://t.me/zhetengsha/957) 两条公开广告。公开网页 HTML 中的表情边界经重建，仍保留原始 HTML 及摘要；这些不是直接提取的完整 MTProto 消息。两条都属于训练与开发材料。

本次四个增量阶段分别完成 1、1、2、2 个 epoch，使用各阶段验证选择的检查点继续。最终阶段选中第 2 个 epoch；本次不是把已有检测结果直接回灌为标签。最终训练含 10,182 条简繁、片段和窗口扩展行，回放 7,899 条原公开训练数据；扩展行数不是独立广告数量。难例增加五倍采样权重，检查规范化后的标签冲突。混合消息仅含正常前文的训练判断不向其广告专属窗口传播正常标签。

基础模型为 HIT／iFLYTEK `hfl/minirbt-h256`，约 1,035 万参数、六层 Transformer、FP16 权重。公开来源仍包括 Chinese-Spam-Dataset、bayes_spam_sniper 审核记录和 tg-ad-guard-bot 开发对照。基础权重采用 Apache-2.0；公开语料未找到明确的数据集许可证，原始语料不随仓库或安装包分发。来源版本、摘要、全部测量及历史阶段见 [RGAdModelSources.json](../Regram/RGAdFilter/Resources/RGAdModelSources.json)，流程见 [Training/README.md](../Regram/RGAdFilter/Training/README.md)。

## 验证结果与适用范围

| 项目 | 结果 | 含义 |
| --- | --- | --- |
| 518 条完整消息开发回归 | 440 条含正常正文全部保留；307 条含广告文字全部清理；78 条纯广告全部隐藏；234 条混合消息清理完整；全部按钮期望通过 | 包含此前 426 条、两个公开样本、21 条编写对照、11 条可见内容和 58 条手机样本；不是未见测试 |
| 公开文本基准 6,663 条 | Precision 97.87%；Recall 32.58%；正常类 FPR 0.73%（TP 1105、FP 24、FN 2287、TN 3247） | 噪声垃圾信息标签下的分类器历史对照，不是实际广告覆盖率 |
| 作者编写的域内验证 55 条 | 正常 30/30 保留，推广 20/25 识别 | 用于检查点与阈值选择；推广召回低于上版 24/25，仍有漏判 |
| 外部机器人开发输入 87 条 | 正常 48/48 未判广告，推广 12/39 识别 | 原始文字分数，未套用显示保护，不代表完整消息结果 |

阈值为 **0.99221**，不是准确率。验证选择仍受公开验证 precision ≥ 98.5%、正常类 FPR ≤ 0.5% 约束。公开测试集多轮作为历史对照使用，开发样本也参与过检查和训练，均不能包装成全新的外部评估。广告范围内所有非空白字符必须消失才计成功，只删联系方式算失败。

实际 iPhone 16 Pro（iOS 27.0.1）上的 Xcode 诊断程序执行同一生产模型、分词器、策略和投影器，518 条正文／按钮结果与 macOS 一致；100 条转换输入和 12 条完整窗口边界对照通过。模型冷加载约 35 ms，整条判断中位约 64 ms、P95 210 ms，包含缓存复用。这不是完整应用滚动帧率，也不表示新 IPA 已覆盖安装到原账号。最终 IPA 另外核对编译后模型与该真机程序的权重一致。

本轮 47 项单元测试、消息桥接及主页预览专项检查通过；完整 arm64 Release 构建和参考 IPA 验收记录保存在 `build-input/ad-filter-34658/`，最终构建状态以该目录报告为准。

当前仍不能识别图片／视频像素、音频、任意未知语言、暗语或所有软文，也没有实现可靠的任意频道主题理解。保留相关服务是审核样本政策，不是全局服务类白名单。系统通知不参与显示投影。开发回归零误删、零残留不等于实际使用零误判；原文保留供纠错。
