# ReSieve 的 iPhone 加速（b34663）

2026-11-16，针对 b34662 在手机上仍明显慢于 macOS 的反馈，比较两端实现并在 iPhone 16 Pro 上执行了同模型对照。模型权重、分词和广告阈值未改；本轮调整执行后端、重复计算和前台调度。

## iOS 原来为什么慢

b34662 的神经网络只在 CPU 上执行。macOS 已经使用 Neural Engine 提前判断明确正常的文本，而 iOS 每个未知窗口都要经过 CPU。iOS 还会在每条消息处理后等待恢复间隔，当前聊天和置顶也要一起等。

现在 iOS 16 及以上的 arm64 真机可以异步载入 `cpuAndNeuralEngine` 后端。加速后端给出的推广概率不超过 0.1 时，按原有的正常内容边界 0.2 继续判断；其余窗口仍由 CPU 计算。广告候选、按钮和上下文使用原来的严格阈值。加速后端尚未载入、不可用或推理失败时，使用 CPU。

没有直接把所有判断切换到 Neural Engine。在手机上比较 10,330 个去重窗口时，两个窗口在 0.99164 广告阈值两侧发生了变化，最大概率差约 0.0432。采用的正常内容门槛覆盖其中 9,164 个窗口，没有出现 CPU 认为高于 0.2、加速后端却低于 0.1 的情况。这是已有样本的实测边界，不保证未知输入永远没有偏差。

## 少算、少等

整段文本按所有窗口的最低分判断。任何窗口已经低于正常内容边界时，后续窗口不能使整段变成广告，因此分类可以停止计算其余窗口。删除广告仍要求所有相关窗口和上下文通过原来的检查。对外提供的精确概率接口始终执行完整 CPU 计算，不能复用正常内容的近似分数。

同一条消息的规范化文本按需复用，最多 128 项、估算 256 KiB。字符串和 token 窗口缓存合计仍为 2 MiB。内存告警同时释放 CPU／Neural Engine 模型及分数缓存，较早发起的异步加载不能在释放后把旧模型装回来。语义磁盘缓存的算法命名空间升为 `semantic-2`。

前台聊天和置顶使用较高执行优先级，进入新页面时可以提前结束主页预览的恢复等待。低电量模式或严重发热时不启用这个捷径；后台和临界热状态仍暂停推理。同一账号只执行一条推理，较旧任务每四次优先调度仍有一次处理机会。主页规则与缓存结果继续独立处理，不等模型。

## 真机结果

设备是 iPhone 16 Pro，系统报告为 iOS 27.0.1（24A446）。使用 Xcode 27.1 编译的独立 Release 验证应用，分别运行 b34662 的 CPU 分类器和本轮分类器，输入为本机保存的同一批样本。结果包含生产分词、规则、语义判断和正文／按钮投影，不包含 Telegram 网络加载与界面绘制。

| 939 条回归样本 | b34662 CPU | 本轮 |
| --- | ---: | ---: |
| 实际调用模型的消息 | 919 | 919 |
| 单条中位耗时 | 59.10 ms | 9.98 ms |
| 单条 P95 | 178.98 ms | 54.02 ms |
| 单条最长耗时 | 503.17 ms | 236.93 ms |
| 整批处理时间 | 69.05 s | 14.34 s |
| 进程 CPU 时间 | 69.24 s | 10.70 s |

两组最终正文、实体、按钮、删除范围和整条隐藏结果完全相同，均没有未完成的推理。1,564 个已标注正常片段全部保留，959 个广告片段全部去除。这里是已有回归集，不能等同于所有频道的识别准确率。新后端实际执行了 8,288 次加速调用和 907 次 CPU 调用。

另一组 82 条真实输入从新建分类器开始处理，包含模型首次载入：整批耗时从 3.36 s 降至 2.27 s；56 条需要模型的消息，中位数从 20.78 ms 降至 7.43 ms，P95 从 211.88 ms 降至 158.77 ms。结果同样一致。冷启动收益小于模型已热起来后的收益，复杂广告仍可能花费一百多毫秒。

单独比较同一个模型窗口时，CPU 中位数为 6.70 ms，加速后端为 0.78 ms。首次加载加速后端约 892 ms，运行时采用异步加载，期间 CPU 可以继续提供结果。整批和单窗口数值不能当成整屏延迟；进程 CPU 时间的下降也不能替代续航、能耗或长时间发热测试。
