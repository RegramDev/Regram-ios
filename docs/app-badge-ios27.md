# iOS 27 App badge 显示兼容

用户设备为 iPhone 16 Pro、iOS 27.0.1，反馈 badge 在各页面均模糊。图片资源清晰，badge 的 UIImageView 没有模糊滤镜或遮罩，并且已经高于应用内的导航内容。普通导航及聊天列表的 EdgeEffect 与 badge 的区域重叠，不能据此确认它们是根因。

原先的 `zPosition = 1000` 只调整同一窗口中的图层顺序，无法处理更外层的窗口合成。b34585 对 iOS 27 及以上、具有灵动岛的设备，将同一个 badge 图片视图移入与主窗口同 scene 的独立透明窗口，窗口级别为 `statusBar + 1`。此处理针对顶部合成路径，不移除或修改导航渐变模糊。

该窗口始终返回空点击命中，不能成为 key window，沿用主窗口的状态栏样式及方向；场景失活、进入后台或断开时立即隐藏。窗口被排除在应用自己的窗口枚举之外，避免被原生弹窗、键盘或分享流程当成展示窗口。原图片选择、横屏隐藏、App Lock 的 alpha 操作仍控制同一个图片视图；切换图片会直接更新不同 badge 的宽度和中心位置，不依赖窗口尺寸是否改变。主页面保留一个空的插入锚点，以避免图片移动后跨父视图插入导致异常。

旧系统及非灵动岛设备沿用应用内显示；关闭 badge 会撤销独立窗口并恢复原视图归属。

验证：新窗口代码通过 iOS 类型检查（warnings-as-errors），完整 `//Telegram:Regram` arm64 Release 构建通过，包含全部六个扩展及 dSYM。

这是兼容处理，尚未证明 iOS 27.0.1 的具体系统滤镜就是根因。按用户要求未使用模拟器，实际遮罩消失、键盘焦点、灵动岛活动、横竖屏切换及前后台显示仍需在 iPhone 16 Pro 上确认。参考包校验结果见该构建的 BUILD-MANIFEST.json。
