# 受保护频道／群组视频保存排查

本次反馈为：开启「允许保存受保护内容」后，可以点击视频保存，但相册中没有文件。修复基于 `origin/master` 的 `91c3dea32d`（13.1.2 / b34643），使用独立分支 `fix/protected-video-save`，原工作区的图标、语言及窗口相关未提交改动保持原样。

## 源码发现

开关已接入 `Message.isCopyProtected()` 与 `Peer.isCopyProtectionEnabled`，频道／群组的保存入口会读取这两个判断。本次没有调整开关、设置备份或保护范围。

保存入口之后存在独立问题：`SaveToCameraRoll` 忽略 PhotoKit 写入成功与否，失败也发送 `1.0` 和完成事件。临时视频复制失败也会进入没有资源的相册事务。因此，播放器菜单、消息长按菜单或分享页可能提示保存完成，但相册没有新条目。下载进度也曾使用 `1.0` 表示完成，无法区分下载完成与写入相册完成。

HLS 保存菜单另外沿用播放器的编码选择；播放器支持的软件 AV1 解码不能证明系统相册接受同一文件。这是视频兼容性风险，尚不能据此断定用户原视频的具体失败原因。

## 修复

- 增加带错误结果的保存接口，播放器保存菜单、消息长按菜单和分享页改用该接口；只有 PhotoKit 明确写入成功才显示完成。失败允许重试，并提供中英繁三种语言提示。
- 下载进度保留相册写入阶段，收到完整文件后停止接受后续下载状态，避免重复写入或取消正在进行的导入。
- 视频先按原内容写入；系统拒绝时尝试一次兼容 MP4 导出，再核对第二次相册写入结果。复制、导出和最终写入失败均返回失败，并清理临时文件；取消后不再发起导出后的导入。
- HLS 保存画质单独选择 H.264／HEVC 表示，不依赖播放器当前画质状态；没有兼容表示时尝试原文件。普通视频可在保存操作中完成剩余下载。

秘密聊天、一次性媒体和付费内容的现有保存入口判断保持原样。本次不涉及 Telegram 服务端的转发限制。

## 验证与边界

`Regram/RGGalleryUI/Tests/run-save-checks.py` 使用生产保存函数和实际 SwiftSignalKit，覆盖 10 个保存场景：PhotoKit 确认、失败、兼容导出重试、复制失败、权限拒绝、取消、临时文件清理及导入期间的后续下载状态。另调用生产 HLS 画质选择，核对两种表示顺序及仅 AV1 表示的回退。已接入 `build-system/check-regram-features.py`。

基线复现命令：

```sh
python3 Regram/RGGalleryUI/Tests/run-save-checks.py --baseline 91c3dea32d
```

基线按预期失败，错误为 `A rejected Photos transaction must not display saved or 100%`。修复后上述回归、现有图库播放回归及语言管理回归通过，三个修改后的 UI 源文件通过 Swift 语法解析。

另将生产保存函数编译为 arm64 iOS 模拟器夹具，使用系统 Photos／AVFoundation 在独立 iOS 27.0 模拟器执行：有效 H.264 MP4 保存成功，视频资源数从 0 增至 1；损坏视频和缺失文件均返回失败，未新增相册条目。夹具、原生编译产物与结果位于本轮忽略目录 `build-input/protected-video-save/`，不包含真实账号数据。
