## 共群发言

- 继续使用 Telegram 的导航栏、主题和返回手势。内容使用 UIKit 原生分组列表：顶部显示查询对象和进度，群组筛选独立为标准 disclosure 行；暂停、继续和重试放在导航栏，并支持下拉刷新。
- 结果使用消息 ID 作为 diffable 列表标识，合并短时间内的进度更新。返回、暂停和继续不再调用整表 `reloadData()`；已有单元格、滚动位置、消息缓存和成功分页游标继续复用。累计搜索页中的旧消息对象不重复排序或触发布局。
- 头像保留 peer 和主题绑定，仅在实际变更时更新；复用时同步读取已缓存的小头像。群组资料发生变化时仍会更新，不使用固定不变的占位图掩盖刷新。
- 普通群跳转显式传入 Telegram 的 `MessageHighlight`。话题群继续使用原生话题导航，该路径已为目标消息设置高亮；迁移前的消息仍按原始 peer 和 message ID 定位。
- 消息查询最多三个群组任务并发，群组发现任务也占用同一预算。查询页大小为 30 条，按需扩展可见结果；下一轮请求至少间隔 0.2 秒，列表更新合并为每 0.12 秒至多一次，不循环刷新已完成的查询。
- 温度轻度升高时最多两个任务；低电量或温度严重升高时一个任务，并延长请求间隔。温度达到 critical 时取消请求，等待系统温度通知后恢复；离开页面、进入后台和手动暂停都会取消请求并使迟到回调失效。

这些措施限制客户端工作量，不能替代真实设备的温度、功耗及弱网体验测试。

## 不保留机器人消息

入口为 Regram Pro → 隐私与过滤 → 防删除与限制解除 →「不保留机器人消息」，默认关闭。它适用于全局防撤回及单独启用防撤回的会话，偏好保存在 App Group，通知扩展使用相同规则；包含设置搜索、控件深链、三种语言和隐私类别备份／恢复／重置。

开启后，已识别为机器人发送的新撤回消息沿正常删除路径处理，包括私聊全局 ID、群组消息 ID，以及普通历史和话题历史同步。用户自己通过 inline bot 发送的消息仍按用户消息处理；匿名或未知发送者不推断为机器人。已有撤回标记的记录不会因打开开关而自动清理。
