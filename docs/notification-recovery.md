# 实验性通知恢复

b34633 起入口为 **设置 → Regram Pro → 通知与提醒 → 实验性通知恢复**，原调试页不再重复展示。现有共享配置和旧键开启状态保留，支持设置搜索及 `tg://rg/settings?page=pro.notifications&item=notificationRecoveryExperiment` 定位链接，并纳入通知类别的备份、恢复和重置。新安装默认关闭；旧通知兼容开关已有的开启状态会沿用，新开关保存后删除旧键。旧开关入口已经移除，也不再因通知兼容设置关闭 CallKit。开关、置顶／提及策略及内容过滤配置按每次推送取快照，同一次推送不会混用切换前后的处理方式。

过滤权限声明继续保留 `com.apple.developer.usernotifications.filtering=true`。签名声明、描述文件声明都不是查询系统实际授权的 API。

## 排查结论

本机留存的 b34586、b34599、b34600、b34609、b34618 参考包均声明通知过滤权限。它们不是设备上经外部工具重签后的最终包，不能据此判断设备授权。仅凭 `You have a new message` 文案也不能判断是证书、解密、共享数据、锁状态、扩展超时还是系统没有运行扩展。

源码排查发现：仅凭签名声明选择空内容过滤、清理遗漏原始回退、共享元数据读取失败会终止扩展、凭据文件锁没有期限、通知进程可能参与数据库升级、媒体缓冲没有容量预算，以及来电接管失败仍返回空内容。主应用从未设置密码锁也不排除共享状态或凭据读取问题；本次没有把开启密码锁作为修复前提。

## 开启后的行为

- **占位识别和清理**：对具有原始加密负载／推送模板证据的完整占位文案，前台阻止展示；扩展及回到前台后清理通知中心中的相同占位。仅凭应用名和正文相同不会删除通知。真实解析的消息、隐私预览加来源标记，保留附件、消息角标及正常提醒。
- **过滤和静音兜底**：有匹配、未过期且声明过滤权限的描述文件时沿用过滤；描述文件明确不匹配时使用仅含应用名、角标和清理标记的 passive 内容。没有内置描述文件的安装继续沿用签名声明路径。清理独立于过滤判断，不依赖空格标题。
- **密钥和凭据**：通知扩展只读取既有的 48 字节数据库密钥；缺失、受保护、格式无效或锁竞争时返回不可用并有限重试，不生成或改写密钥。凭据读取的进程内锁和文件锁增加期限；未知状态保留隐私，不初始化密码凭据。
- **元数据和数据库**：通知启动使用可失败的异步账号管理器，不因原子快照暂时不可读而终止。数据库打开及初始事务遇到不可用时返回失败，缩短锁等待；不创建新数据库或迁移账号数据库。正常事务的严格失败检查保留，不在失败后继续非原子写入，也不删除数据库。
- **推送路由**：主应用实际提交解密路由后才注册加密推送。暂时缺少密钥时按退避间隔重试；本地记录不可用不用于判定 APNs token 失效，不自动退出其他会话。扩展路由未命中不直接认定为其他会话。
- **资源和期限**：通知图片优先适合预览的尺寸，单资源最多 2 MiB、一次推送的富媒体资源预算最多 6 MiB；分片的偏移、范围和累计大小在分配缓冲前校验。内嵌自定义表情最多两个。超出预算或时间不足时保留文字，不继续昂贵的媒体增强。连接预算从接收推送时计算，仍保留独立的 24 秒主动完成期限。
- **密码锁**：只有权威凭据明确表示已移除密码时，才忽略陈旧锁文件；主应用清理对应的陈旧手动锁定与失败次数时再次核对开关及当前密码配置。无法读取锁状态时保留隐私，不删除凭据或会话。
- **回调和来电**：前台通知账号判断增加等待上限并只完成一次；CallKit 接管失败时回退普通来电提醒，保留真实锁定时的隐私行为。

关闭实验后使用原有通知路径；主应用的密码配置、默认数据库读写和连接设置不启用上述通知专用模式。其他已有通知过滤、静音及提及设置继续生效。

## 调试页缓存清理

同页新增 **清除缓存**，确认后通过现有存储引擎清除当前账号的媒体缓存，并清除网页内存／磁盘缓存和系统 HTTP 缓存。执行时显示等待状态，完成后显示反馈，防止重复启动。

保留账号、聊天数据库、设置、书签、证书、下载的更新 IPA、网页登录数据和已存入编辑记录的图片。仅缓存中的媒体可能需要重新下载；已被服务端删除的媒体可能无法重新获取。这不等于“清除全部本地数据”。

## 平台边界与验证

Apple 的[通知扩展说明](https://developer.apple.com/documentation/usernotifications/unnotificationserviceextension)和[过滤权限说明](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.usernotifications.filtering)决定最终展示行为。passive 是静默提醒，不等于服务器取消推送。覆盖安装时系统可能不启动扩展，也可能在扩展完成后立即挂起它；没有实际过滤授权时，无法保证后台所有横幅都不出现或延迟清理必定执行。

本地检查覆盖原生通知内容、过滤资格与预览保护、开关状态、真实凭据锁竞争、只读密钥读取、资源预算、设置迁移与备份，以及一／二行布局。调试页、通知扩展、账号管理器和凭据集成已进行 Xcode 27 iOS SDK 局部类型检查；跨模块新增接口使用签名适配，并非完整链接验证。

b34619 已完成 Xcode 27 arm64 Release 构建及主应用／六扩展包校验，安装身份和权限与 b34618 一致，通知过滤权限声明保留。验证针对同一份已构建 IPA；尚未在用户证书、设备重启、安装覆盖或真实 APNs 环境下验证，不能表述为已根治全部空通知。
