# b34584 字体文件导入修正

用户反馈 TTF、OTF、TTC 能在文件浏览器中显示，但点击没有反应。b34583 使用 SwiftUI `fileImporter`，其打开外部文件的流程在用户设备上仍然失败；调整类型过滤不足以解决该问题。

字体页现在复用 Telegram 的 `legacyICloudFilePicker`，以 `.import`（`asCopy: true`）取回应用容器中的副本。选择器接收 `public.item`，避免文件提供者的类型标注阻挡字体文件，再由 CoreText 校验实际内容。取消和滑动关闭都重置导入状态；成功后自动选中当前语言类别，必要时切换到字体支持的类别。

存储层解析已读取的字节，保留 64 MB 限制，不再把缺失的文件大小元数据直接当作超限。字体保存后清理选择器副本；不会删除文件提供者中的原文件。TTC 仍使用第一个字型。

验证：字体页 iOS 类型检查和完整 arm64 Release 构建通过；macOS 主机检查使用生产存储实现，覆盖 TTF、中文字体、OTF、TTC、临时副本删除后的持久读取、集合字型保留、重复文件和大小限制。实际文件选择交互尚未在用户设备验证；按要求没有使用模拟器。

App badge 检查：图片资源清晰、UIImageView 没有模糊或遮罩；聊天列表及普通导航的 EdgeEffect 都位于应用内容树内，badge 则是其上方的根视图子视图。它们的区域重叠不能证明导航模糊会覆盖 badge。用户补充各页面均出现模糊，因此继续检查全局层级及系统状态栏或灵动岛的合成；根因仍未确认。本次没有删除或调整导航模糊效果，也没有将 badge 标为已修复。
