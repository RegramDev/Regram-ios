# Regram typography

The application bundles the font catalog and license notices. Font binaries are downloaded explicitly when a family is selected, validated against `RGFontCatalog.json`, and retained for offline use. Partial or corrupt families are not published. `FONT-SOURCES.json` retains source/version/license metadata; the files under `Fonts/` are host test fixtures and are not included in the application target.

English/Latin and Chinese are selected independently, with separate checkboxes for chat messages and the main interface. Han characters, CJK punctuation and full-width forms follow the Chinese selection; ASCII letters, digits and punctuation follow the Latin selection. Missing glyphs keep the system fallback. Code, icons and large emoji retain their dedicated rendering. Downloaded and imported selections participate in cache keys and presentation refreshes.

The native document picker copies TTF, OTF and TTC files before CoreText validation, with a 64 MiB limit. Completion comes from explicit selection, cancellation or interactive dismissal, so file-provider navigation cannot race a deferred cancellation. All supported TTC faces are listed individually. Their IDs combine the file hash and face index; existing hash-only selections continue to identify face zero. Collection faces share one stored file. Removing the last face reclaims that file, and deleting an active selection restores the corresponding system font. Imported names can be edited, and downloaded files can be cleared separately from imports.

Downloaded Anthropic/Google and imported fonts use their actual face in previews. Undownloaded choices show a download prompt. Rendering performs no network requests.

Run `python3 build-system/check-regram-features.py` on macOS for the standalone Foundation/CoreText regressions and storage tests. The storage harness uses temporary folders, local HTTP fixtures and the real ZipArchive implementation, covering hashes, archive extraction, cancellation, all three import formats, TTC faces, duplicates, rename, deletion and storage accounting. It does not touch Telegram accounts or launch a simulator. UIKit picker gestures, real iOS layout, system font fallback differences and provider behavior still require device validation; an arm64 application build verifies compilation rather than those interactions.
